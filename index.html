// Project Description

Greetings agent, this highly-classified project consists of designing and implementing a smart remote listening device using the TI CC3200 platform. The purpose of the project was to create a system capable of monitoring its surroundings, detecting relevant events, recording audio, and sending alerts or data to a remote user. TI CC3200 LaunchPad is used as the main hardware platform for developing an embedded monitoring system. The system was designed around the idea of detecting nearby activity through sound and detecting unwanted movement through the onboard accelerometer. When activity was detected, the device would record audio samples and transmit them over Wi-Fi using AWS IoT services. Audio was sampled by the microcontroller, converted into a compact 8 bit format, encoded into base64, divided into chunks, and transmitted through the AWS IoT device shadow. A cloud side process was then intended to reassemble the audio data into a WAV file and provide access to the user through email. The plan was to also implement a high level state based workflow in which the device would remain idle while monitoring, transition into recording or tamper states when triggered, and then notify the user before returning to monitoring. The final code met all these goals with the exception of text to speech by implementing a complete embedded state machine with disarmed, idle, recording, audio sending, tamper sending, and error states.

// Challenges

  • AWS IoT shadow has a hard 8kB limit per post — only ~1 second of audio at reasonable quality
  • Explored direct S3 capture; settled on chunking device memory into 8 posts
  • Lambda is stateless — used S3 to persist chunks across invocations
  • Microphone quality caused audio to be higher pitched but still distinguishable

// Implementation

Developed in Code Composer Studio using TI CC3200 support libraries. The system boots, connects to Wi-Fi, and enters a disarmed state waiting for SW3 to arm it.

  • Protocols: I2C (BMA222 accelerometer), ADC (microphone), GPIO (button), HTTPS/TLS (AWS)
  • Microphone: Sampled on ADC channel 1 — baseline measured, deviation threshold triggers recording
  • Recording: ~10 seconds at 4000 Hz, 14-bit samples reduced to 8-bit and stored in buffer
  • Tamper: Accelerometer X/Y/Z read continuously — movement beyond threshold sends alert
  • Chunking: Audio split into 8 base64 chunks, each posted to AWS IoT shadow separately
  • Lambda: Triggered by IoT Rule — stores chunks in S3, reassembles on final chunk, appends 44-byte WAV header, emails presigned URL

// System Architecture

  • TI CC3200 LaunchPad as the core hardware platform
  • Microphone connected through ADC channel 1 for sound detection and recording
  • Built-in BMA222 accelerometer via I2C for tamper detection
  • SW3 push button via GPIO for arming and disarming the device
  • Wi-Fi connection over HTTPS/TLS to AWS IoT device shadow
  • Lambda function triggered by IoT Rule to handle alerts and audio
  • S3 bucket stores audio chunks and reassembles into a WAV file
  • Presigned URL emailed to user for audio download

// State Machine

  • Device begins in a disarmed state waiting for the user to press SW3 to arm it
  • Once armed, the system calibrates the microphone and accelerometer baselines
  • During idle monitoring, the system checks for button press, tamper, or noise events
  • If noise exceeds threshold, device enters recording state — about ~10 seconds at 4000 Hz
  • If accelerometer exceeds tamper threshold, device sends a tamper alert
  • After recording, device enters sending audio state and transmits 8 base64 chunks
